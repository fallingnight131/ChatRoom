# ADR-0161: Verify Unsigned Windows Signing Intake

- Status: Accepted
- Date: 2026-08-12
- Owners: project maintainers
- Related milestone: M4

## Context

The ordinary Windows CI now produces a canonical CMake unsigned artifact with
installer and parity evidence. Rebuilding C++, Qt, and third-party dependencies
on a private-key-capable runner would unnecessarily enlarge the signing trust
boundary. Downloading an ordinary artifact without independent verification,
however, would let stale, substituted, extra, or partially declared bytes reach
the certificate operation.

## Decision

- Treat ordinary CI output as untrusted input to protected signing.
- Add a provider-neutral verifier for the complete artifact directory, not only
  its manifest file.
- Require closed schema-3 identity: canonical version and revision, pinned Qt,
  MSVC 2022/x86_64 Windows, `buildSystem: cmake`, verification channel, and
  explicitly unsigned status.
- Require sorted unique client entries, exact unsigned NSIS identity, parity
  evidence metadata, client/helper/Qt Core/platform/SQLite runtimes, and exactly
  one root libsodium DLL.
- Reject case-insensitive collisions, signing/debug/key/server material,
  symbolic links, non-regular entries, missing or undeclared files.
- Require `SHA256SUMS`, every manifest size/SHA-256, and final bytes to agree.
- Run the mutation suite in both baseline and native Windows policy jobs.
- Keep Authenticode inspection outside the portable verifier. The protected
  Windows step must additionally observe `NotSigned` before signing.

## Consequences

A future signing runner needs only the checked-out packaging policy, verified
unsigned artifact, NSIS, Python, Windows SDK signing tools, and its externally
provisioned certificate. It does not need a compiler, Qt installer, vcpkg, or
network dependency resolution.

This verifier proves artifact integrity and identity, not build provenance,
malware absence, certificate custody, or a successful signature.

## Migration and Rollback

The protected workflow must invoke this verifier before certificate-store access
or mutation. If schema changes, expand the producer and verifier together; never
accept unknown fields for convenience. Rollback disables protected signing and
leaves the unsigned verification artifact unchanged.

## Verification

- accept one complete artifact generated by the canonical manifest code;
- reject byte mutation, missing/extra files, qmake/open-schema identity,
  duplicate checksums, requested identity mismatch, and symbolic links;
- compile both verifier and tests on the repository Python baseline;
- parse both workflows and retain zero signing/private-key logic in ordinary CI.
